# KateLauncher — Linux-середовища

Linux-програми (з proot-distro/Ubuntu в Termux, box64, Wine…) відкриваються як звичайні плаваючі вікна лаунчера.
Є два режими показу, їх можна вибрати для всього, для середовища чи для окремої програми:

| Режим | Як працює | Коли обирати |
|---|---|---|
| **X11** (через Xwayland) | У середовищі працює `Xwayland`, до нього підключений вбудований менеджер вікон лаунчера (XWM). Програми бачать справжній X11, як в XFCE: ті самі команди, `DISPLAY=:42`. | Firefox, Ren'Py/SDL через box64, Wine, Electron, старі GTK/Qt-програми |
| **Wayland** | Програми підключаються просто до Wayland-сокета лаунчера. Без Xwayland. | Програми, що нативно вміють Wayland |

## Як це влаштовано
```
Лаунчер (Android)                         Termux (uid Termux)
 ├ LinuxStore: середовища, програми        ┌─ скрипт RUN_COMMAND (тримач сеансу: wake-lock, сповіщення)
 ├ TermuxLauncher ── Binder або RUN_COMMAND┤   └ app_process … HostMain
 ├ WaylandSource ◄── Binder (oneway) ────► │        ├ композитор (C, JNI): Wayland-сокет + XWM
 ├ SessionState (облік запусків)           │        └ Session (Java): черга запитів, процеси, журнали
 └ LinuxWm → WinFrame/WinContent           │              ├ <команда середовища> sh -c '<змінні + ваша команда дослівно>'
                                           │              └ Xwayland :42 -rootless   (лише в режимі X11)
```

### Сеанс і запуск (`Session`)
* Лаунчер формує **запит** (текст) і віддає його сеансу: Binder-ом, якщо сеанс уже працює (без Termux), інакше —
  коротким скриптом через Termux `RUN_COMMAND`. Скрипт кладе запит у `$TMPDIR/katewl/ctl/` і, якщо хоста немає,
  **запускає його на передньому плані** — цей процес і тримає Termux «живим» (сповіщення, `termux-wake-lock`).
* Хост запускає кожну програму як дочірній процес, веде облік (pid, стан, код виходу), пише журнал
  `logs/app-<id>.log` (з точною командою зверху) і повідомляє лаунчер. Невдалий запуск без вікна → тост із кодом.
* **Мітки процесів.** Кожен запуск несе `KATE_RUN=<id>` (і `KATE_APP_ID`). Програму й усе, що вона породила
  (навіть крізь proot), знаходять і завершують за міткою в `/proc/*/environ`, а не за PID.
* **Залишки після аварій.** Під час старту нового сеансу вбиваються всі процеси з мітками попереднього. Крім того,
  перед запуском програми всередині середовища прибираються застарілі замки профілів Firefox (`lock`, `.parentlock`)
  і Chromium/Electron (`SingletonLock`…), якщо процесу, на який вони вказують, уже нема. Саме це лікує
  «Firefox уже запущено», що лишався після виходу з Termux.
* **Життєвий цикл.** Сеанс живе, поки є програми чи вікна, і завершується після простою (налаштування, за
  замовчуванням 5 хв; 0 — ніколи). Якщо лаунчер перезапустили («Перезапустити» в налаштуваннях) — програми й вікна
  **лишаються**: після повернення лаунчера композитор оголошує всі вікна наново.
* **Кнопки в налаштуваннях** («Сеанс і запуск»): стан сеансу, список запущених програм із «Зупинити», «Зупинити
  всі програми», «Скинути сеанс» (вбиває все, навіть коли хост уже не відповідає), «Журнали…».

### Режим X11 (XWM)
Xwayland у режимі `-rootless` віддає композитору вікна X11 лише тоді, коли хтось виконує роль менеджера вікон X11.
Композитор сам підключається до сокета `…/tmp/.X11-unix/X42` і розбирає протокол X11 вручну (без libxcb), див. `jni/xwm.h`:
* перехоплення `MapRequest`/`ConfigureRequest`, `Composite`-перенаправлення, EWMH (`_NET_SUPPORTED`, `_NET_WM_STATE`, …);
* зв'язування вікна X11 з поверхнею Wayland через `WL_SURFACE_ID`; заголовок, клас, мінімальний/максимальний розмір,
  `WM_DELETE_WINDOW`, повний екран/максимізація, `_NET_WM_MOVERESIZE`;
* вікна *override-redirect* (меню, підказки) стають popup-ами вікна-власника (`kind=2`), програма закриває їх сама;
* **розташування:** активне вікно стоїть у (0,0), решта «запарковані» у далеких слотах без перетину — інакше X вибирав
  би «верхнє» вікно під курсором, а не те, на яке натиснули. Перед подіями Wayland X-сервер синхронізується
  (`GetInputFocus`), тож кліки не потрапляють у чужі вікна.
* буфер обміну між Android і X11 бридж робить сам Xwayland (через `wl_data_device`).

Потрібно в середовищі: `apt install xwayland` і вхід `proot-distro login … --shared-tmp --` (спільний `/tmp`, щоб було
видно сокети `wayland-kate` і `.X11-unix/X42`).

## Керування й діагностика
* «Журнали…» в налаштуваннях: сеанс (композитор, помилки запуску), Xwayland, окремо кожна програма.
* Перемикач «Докладний журнал»: пише в журнал сеансу підключення клієнтів, фокус, кліки (`вікно → поверхня є/НЕМАЄ`),
  клавіші, роботу XWM. Якщо програма «не реагує» — видно, чи доходять події до композитора.
* Без лаунчера (з Termux): `cat $TMPDIR/katewl/host.log`, `cat $TMPDIR/katewl/logs/app-*.log`.

## Збірка
`sh build.sh` у Termux. Для Linux-вікон потрібні `clang` та `jni.h` (`pkg install clang ndk-sysroot`), для
вирівнювання нативної бібліотеки в APK — `zipalign`. Без них збірка проходить, але справжні Linux-вікна не працюватимуть.

## Тести на ПК (Linux)
`jni/test_main.c` — тестовий хост ядра: читає команди зі stdin (`focus`, `click`, `tap`, `cfg`, `resync`…), друкує події.
```
sh jni/tests/run_xwm_test.sh        # справжній Xwayland + xterm/xev + ASan/UBSan; 0 = усе гаразд
```
Для ручних дослідів: `gcc -g -fsanitize=address,undefined jni/kwl.c jni/test_main.c -o kwltest -lpthread`,
keymap — `java -cp … KeyTable /tmp/kate.xkb`, далі `./kwltest /tmp/kd /tmp/kate.xkb` і Wayland-клієнт із
`XDG_RUNTIME_DIR=/tmp/kd WAYLAND_DISPLAY=wayland-kate`.

## Не зроблено / обмеження
* Немає `zwp_pointer_constraints`/`relative_pointer` (захоплення миші в іграх), `wl_touch` (дотик працює як миша),
  text-input, dmabuf/EGL (клієнти малюють програмно).
* Вказівник (курсор) не малюється.
* Режим X11: програми рендеряться з масштабом 1 (Xwayland), «різкий» режим (масштаб 2) на них не діє.
* Якщо Android убиває Termux (немає виключення з оптимізації батареї / обмеження дочірніх процесів — див. розділ
  «Налаштування» в застосунку), сеанс і програми гинуть; після відновлення залишки прибираються автоматично.
